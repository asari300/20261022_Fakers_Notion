# ADR-0008 データベースはページの Y.Doc の中のブロックとして持つ

- 状態: **Accepted**（2026-10-25、S011。テーブルのビューの 2 タブの同期を E2E で確かめた）。

## 背景

- P3 は Notion 風のデータベース（テーブル・ボード・リストのビュー、プロパティ、フィルタとソート、フォーミュラ）を作る（[roadmap.md](../roadmap.md)）。[features.md](../features.md) の方針は「ビューはページの中のブロック。データは `Y.Map` の行」。
- 文書の同期・永続化・Presence はページ（1 つの `Y.Doc`）単位でできている（[ADR-0003](0003-crdt-yjs-yrs.md)）。

## 決定

- **データベースは `type: "database"` のブロック**で、ページの `Y.Array("blocks")` に他のブロックと並ぶ。`text`（Y.Text）は表の題名。
- **列は `columns: Y.Array<Y.Map{id, name, type}>`、行は `rows: Y.Array<Y.Map{id, <列の id>: 値}>`** をブロックの `Y.Map` に持つ。列の `type` は `text` / `number` / `checkbox`（日付と選択は後で足す）。
- **セルの値は文字列・数値・真偽値をそのまま置き、セルごとに後勝ち**にする（Y.Text にしない）。同じセルを 2 人が同時に打つと片方が消える（shortcut。困ったら Y.Text にする）。
- **値は列の型と合うときだけ読む**。列の型を変えても値は消さず、合わない値は空として表示する（型を戻せば戻る）。壊れた値で表全体が読めなくならない。
- 列を消すと各行のその列の値も同じ transaction で消す。種類を別のブロックに戻しても表（`columns` と `rows`）は消さない。
- Rust の `blocks_json` と Elixir は表を読まない（種類と題名だけ）。表を読むのはクライアントの FFI（`snapshot` がブロックの JSON に `table` を足す）と `fakers_shared/database`。

## 結果

- 新しい同期・永続化の仕組みは要らず、既存のページの経路にそのまま載った。2 タブの同期・列の型の変更・行の削除を E2E で確かめた。
- 別のページから同じデータベースを参照する（Notion のリンクドビュー）、行をページとして開く、ページをまたぐリレーションはできない。必要になったら、データベースを独立した文書にして参照する形に移す（その時に新しい ADR を書く）。
- 行の数が多くなると `snapshot` は毎回表全体を JSON にする。大きな表は計測してから考える。
