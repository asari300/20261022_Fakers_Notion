キャレットと再接続

P2 の 1 回目。リモート編集でキャレットが飛ぶ問題を直した

リモート更新を当ててもキャレットは動かない。title も見出しに追従し、再接続も E2E で確かめた
目的

このセッションでやること

  • ブロックは制御された <input>。リモート編集のたびに Lustre が value を書き、手元のキャレットが末尾へ飛んでいた
  • 最初の見出しを title 列へ写す
  • サーバー停止中の編集が、再起動後に相手のタブへ届くことを E2E で確かめる
  • 文脈: S004 で worktree の実体を USB へ移した（/mnt/usb_sd64c/Fakers_Notion/worktrees/、.git-worktree/ にシンボリックリンク）。コールドビルドは SD で 52 分、USB で 24 分
決定と理由

決めたこと

項目決定理由
キャレットapplyRemote で Y.RelativePosition に変換し、更新後に setSelectionRange相対位置なら、手前への挿入でもキャレットが同じ文字に付いてくる
Lustre との折り合い先に el.value を書いておく同じ値の再設定は、HTML 仕様でキャレットを動かさない
titledo_flush で最初の見出しの文字列を書く。見出しが無ければ変えない保存の経路に乗せれば、クライアントに title の送信が要らない
入力要素<input> のままキャレットの目的には足りた。contenteditable は後回し
