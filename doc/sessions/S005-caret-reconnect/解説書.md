## 1. 目的

P2 の 1 回目。次の 3 つをやった。

- リモート編集を受けたとき、手元のキャレットが末尾へ飛ぶのを直す
- 最初の見出しを `title` 列へ写す
- サーバー停止中の編集が、再起動後に相手へ届くことを E2E で確かめる

文脈として、S004（2026-10-23）で worktree の実体を USB の `/mnt/usb_sd64c/Fakers_Notion/worktrees/` へ移し、`.git-worktree/` にはシンボリックリンクを置いた。コールドビルドは SD で 52 分、USB で 24 分だった。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| キャレット | `src/Gleam/fakers_web/src/fakers_web/session.ffi.mjs` の `applyRemote(doc, update)` で、選択を Y.RelativePosition に直して更新を当て、絶対位置へ戻して `setSelectionRange` する | 相対位置なら、手前への挿入でもキャレットが同じ文字に付いてくる |
| Lustre との折り合い | `el.value` を先に書く。Lustre が同じ値を設定しても、HTML 仕様ではキャレットは動かない | ブロックは制御された `<input>` で、Lustre が `value` を書き直すため |
| 対象 | フォーカス中の要素が `id="block-<id>"` の input のとき。channel の "sync" と "update" の両方で使う | 他の要素は従来どおり |
| title | `DocumentServer.do_flush`（`src/Elixir/fakers/lib/fakers/documents/document_server.ex`）が、`Native.blocks_json` と Gleam の `:fakers_shared@block.decode_blocks` で最初の見出しの文字列を取り、`title` 列へ書く。見出しが無ければ変えない | 保存の経路に乗せれば、クライアントから title を送らずに済む |
| 入力要素 | `<input>` のまま | ロードマップは contenteditable だが、キャレットの目的には input で足りた |

## 4. 再現手順

```bash
git diff main -- src/
cd src/Elixir/fakers && mix test
uv run python src/Python/e2e/two_tabs.py
```

E2E（`src/Python/e2e/two_tabs.py`）に足した手順:

- 5: タブ 1 のキャレットを 5 に置き、タブ 2 が先頭に "AB" を挿入する。タブ 1 のキャレットは 7 で、フォーカスも残る
- 6: 見出しを編集すると、`/api/pages` の title が変わる
- 8: サーバーを止め、タブ 1 でオフライン中に入力し、再起動する。再接続後にタブ 2 へ届く

検証の結果（数字）:

- Elixir は 20 テスト、失敗 0。新しいテストは「flush で最初の見出しの文字列が title に写る」
- E2E は成功。タブ 1 からタブ 2 まで 26 ms、オフライン中の編集は再起動開始から 3896 ms で届いた
- 逆の確認として、修正を無効にするとキャレットの検査が落ち、キャレットは `[True, 18, 18]`（末尾へ飛ぶ）だった

## 5. 次回

積み残し:

- まだ `<input>` で contenteditable ではない。キャレットの目的には足りているが、ロードマップとは違う
- IME の変換中にリモート更新が入ると、フォーカス中の input の書き換えで変換が壊れうる。未対応
