決定と理由

決めたこと

項目決定理由
載せる先Phoenix.Presence の meta（別イベントの broadcast にしない）後から入った人にも今のカーソルが届く。切断した人のカーソルは自動で消え、後片付けのコードが要らない
位置Y.RelativePosition を base64 にした文字列絶対位置だとずれる。次のスライド
user_idjoin ごとにサーバが振るクライアントに名乗らせない
描画Lustre の外。画面に固定した透明な層<input> の中にはキャレットを描けない。Lustre の差分描画ともぶつからない
決定と理由

なぜ絶対位置でなく相対位置か

絶対位置（文字の番号）

受け手の手元には、相手にまだ送っていない編集がある。その分だけ番号がずれる

相対位置（Y.RelativePosition）

番号ではなく、特定の文字に付く。受け手の未送信の編集でずれない

  • キャレットの手前に文字を打っても値が変わらない。送信側は同じ値なら送らず、入力のたびの送信が要らない
  • 送るのは 1 フレームに 1 回まで
決定と理由

user_id と入力の検証

入力サーバの扱い
user_idjoin ごとにサーバが生成する。join の返事に入れて本人へ返す
名前クライアントが送り、trim して 32 文字に切る。空なら「ゲスト」
cursor の block文字列で 64 バイトまで
anchor / head文字列で 256 バイトまで。中身（相対位置）は見ない
形が違う"bad cursor" のエラーで返す。%{} はカーソルを消す

Presence の meta は同じページの全員へ配られるので、長さと形はサーバで検める
